Streamax eSIM/Technology

What is actually inside the device.

An eUICC, an operating system built for a decade of write cycles, and a package that survives an engine bay. This page is the technical detail behind the two form factors Streamax fits.

Definitions

eSIM, eUICC, profile — three different words.

eSIM is the everyday name for a SIM built into a device. Instead of inserting plastic, the device downloads an operator profile — much like installing an app. Once it is there, you can activate it, switch operator or change plan remotely: no opening the device, no swapping cards.

eUICC — embedded Universal Integrated Circuit Card — is the architecture that makes that possible. It is the standard that lets one physical module download, store and switch between multiple operator profiles over the air.

A profile is one operator's subscription: its keys, its network-access application, its files and its applets. A eUICC can hold several; exactly one is active.

Both Streamax form factors are eUICC-capable and need no change to the terminal. Any modem compliant with the usual UICC standards (ETSI TS 102.221, TS 102.223) drives them as if they were an ordinary SIM.

Operating-system variants

The same silicon ships with one of three OS builds. Which one you get depends on what the deployment has to do.

USIM

Classic UICC OS for 2G / 3G / LTE. SIM and USIM network-access applications, remote UICC management over SMS.

Advanced

Everything in USIM plus CDMA network compliance, IMS access through an ISIM, and remote UICC management over HTTPS.

MultiSIM

Multi-subscription UICC. Holds several independent operator profiles — as though it were several UICCs — and swaps between them on command. This is the eUICC build, developed to the GSMA embedded-UICC specifications.

Form factors

Soldered or removable — both are industrial.

The difference is mechanical, not functional. Pick the soldered chip for sealed, high-vibration installs; pick the card when somebody needs to be able to take it out.

Solder-down · chip on board

eSIM chip — MFF2

An M2M identity module in the standardised MFF2 surface-mount package, soldered straight onto the device board. No slot, no spring contacts, nothing to work loose or corrode. This is the default for sealed, automotive-grade builds.

  • Immune to vibration and slot fretting
  • Sealed and tamper-resistant — no SIM to remove
  • Qualified for solderability, vibration and mechanical shock

Industrial SIM card

The same ruggedised silicon in a removable card, delivered in a triple-cut frame: punch it out as 2FF (mini), 3FF (micro) or 4FF (nano) to fit whatever is in front of you. Ruggedised card body and lead-frame metallisation, not a consumer card in an industrial box.

Profile lifecycle

How a profile gets on, gets used, and gets removed.

A multi-subscription UICC turns one module into several independent profile areas. Operators can coexist on the same chip and be administered remotely by a subscription management server.

  1. Independent profile areas

    Each operator profile lives in its own secure storage area, implemented as a GlobalPlatform security domain. Once a profile is loaded, its content is private to that operator — only the profile's owner can administer what is inside it.

  2. Loading a profile

    At least one profile is loaded and enabled at issuance, exactly like an ordinary UICC. Further profiles can be added before issuance or later over the air, over an HTTP channel; the modem has to support BIP. A profile does not have to be enabled when it is loaded.

  3. Enabling a profile

    Enabling makes a subscription the active one. Only one can be active at a time, and enabling a profile automatically disables the previous one. The module prepares the swap and then asks the device to reboot with a Refresh command — the change takes effect on that reboot, never mid-session.

  4. Terminating a subscription

    The subscription manager removes a subscription and clears its profile area. The memory is released and can be reused for a new profile.

  5. Administering the live profile

    While a profile is active, its operator manages it from their usual OTA platform over SMS, HTTPS or both — remote application and file management, the same as any UICC.

Network-access applications

A profile can carry one or more NAAs, exactly as a traditional UICC does: SIM, USIM, CSIM, ISIM.

Transversal applications

Operator applets sleep when their profile is disabled. Transversal applets are not attached to any profile and stay active whichever one is enabled — cryptographic services for the terminal, quality-of-service monitoring, secure storage for device data. They live in their own security domain with GlobalPlatform remote application management.

Switching operator is a reboot, not a visit. The module stages the swap and requests a refresh; the device comes back on the new profile. Nothing in the vehicle is touched.

Why it lasts

An operating system designed around memory wear.

Non-volatile memory has to be erased before it is rewritten, and every erase degrades the cell a little. After enough cycles on the same page, it stops holding its value. Robust smart-card silicon manages roughly 100,000 to 500,000 cycles per page — but endurance is only half silicon. The other half is what the OS does with it.

The extended-life OS in these modules was written for the automotive requirement of 17 years and carried across to the industrial parts with a 10-year target. It attacks wear three ways:

  1. Do not write what you do not need to

    The OS avoids redundant NVM updates altogether — the cheapest cycle is the one that never happens.

  2. Spread the wear

    Data is reallocated around memory so cycling is distributed evenly across pages instead of hammering the same few.

  3. Detect and retire failures

    Worn pages are detected and blacklisted before they can corrupt anything.
